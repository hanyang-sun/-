# 实时积木压住敌人的局部重寻路

日期：2026-11-06。用户确认：全局仍可通行时，新敌人立即使用新入口路线；被新增积木压住的旧敌人先沿其原路线脱离，再重寻路。真正全局无路时仍保留完整旧入口路线。

## 复现

原实现只要一个旧敌人无法从当前位置连接新地图，就保留所有入口路线。固定地图加入一块墙后，两个入口到核心仍有有效路线，却提示“敌人 6 无法从当前位置到达核心”。持续出怪时新敌人继续走旧路进入新墙，至少五秒仍无法恢复。复现脚本在本机 `.scratch/path-overlap-probe/`；该回路驱动正式 `BattleSimulation`，没有读取仿真真值用于预测。

## 实施约束

- 有效候选地图立即更新完整入口路线，新敌人从新路线出生。
- 能连接新路线的旧敌人立即重寻路，其他旧敌人保持其当前位置、原路线及进度，标记等待重新连接。
- 待连接敌人在离开当前导航格后再尝试连接，避免每帧重复 A*。无需新的 RGB 变化才能恢复。
- UI 将局部脱离提示与全局堵路提示分开；全部旧敌人脱离或被消灭后自动清除局部提示。
- 全局堵路、入口变化、核心变化、严格旧模式、暂停和波次状态沿用现有规则。采样参数继续为 0.25 秒 / 0.01 秒 / 一帧。
- 回归覆盖持续出怪不再反复进入新墙、旧敌人不瞬移、暂停、移走新墙立即恢复，以及全局无路回退。

## 验证结果

- `pwsh -NoProfile -File Tests/RunLogicChecks.ps1`：Release 全量 1105 项断言通过，含新增局部重寻路 19 项；既有严格等待、全局堵路、塔更新和暂停检查继续通过。
- `pwsh -NoProfile -File Tests/RunSimulationDualWindowChecks.ps1 -CheckClass LiveProjectionRefreshChecks`：Unity 6000.3.24f1 隔离场景 130 项通过。使用自动 RGB 与稳定确认触发新墙，不调用重试或手工识别；验证三个入口的新路线、实际投影窗口、面板局部提示及脱离后清除。
- 修正面板在计算最新提示之前刷新造成的一次旧提示残留。控制器不再每 0.25 秒重试整图，局部重寻路由战斗模拟按敌人移动触发。
- 当前 C/main 的塔使用章鱼图案，旧联调断言中的 `BattleTowerAim` 已更新为实际 `OctopusFace`，默认禁用的塔靶纹样不再被断言为必须存在；未改变产品视觉效果。
- 验收限于 Unity 仿真；没有实机摄像头或投影仪测试，也没有更改 RGB 分类或三帧稳定确认策略。

# 投影贴合问题：成因、评估标准与校正方案

状态：分析完成，方案未实施
日期：2026-11-06
适用：`真实投影` 分支（`SimulationProjectedLight` + `Resources/ProjectedLight/*.shader`），Unity 6000.3.24f1，Built-in 渲染管线

## 摘要

虚拟投影仪目前把内容当作“贴在桌面上的平板幻灯片”，因此棋盘平面以上的物体（积木顶面）会出现几何偏移：中心几乎不偏，边缘最多偏约 0.385 格。

该偏移由投影几何自然产生，但本项目最终落地真实硬件、由人观看，**观众会把它读作“系统没对准”，而不是“投影仪的物理特性”**。因此判定为“未做部署校正”，而非需要保留的真实性。

推荐改为**投影仪视角烘焙**（方案 B）：让烘焙内容的相机与投影仪同位姿、同视场角，使投影落点与几何位置严格一致，同时完整保留遮挡、表面反射率、入射角和距离衰减等光学效果。

---

## 1 现象

在 10×10 棋盘上，投影图案（格点、角色高亮、变更环）与积木顶面不对齐：

- 棋盘中心附近几乎看不出偏差
- 越靠边缘偏移越大
- 桌上无积木处（`y = 0`）没有偏移

---

## 2 评估标准：给人看，还是给相机看

投影的消费方有两个，优化方向不同：

| 维度 | 相机 / 算法 | 人眼 |
| --- | --- | --- |
| 在乎 | 像素可分、颜色可判 | 图案是否对齐、亮不刺眼、闪不闪 |
| 正交还是透视 | 影响采样坐标 | 完全无关 |
| 高度偏移 | 无所谓 | 第一眼读作“没对准” |

本项目最终以真实硬件落地，观众是人。由此确定分工：

> **几何要校正（服人），光学要保留（像光），采集参数独立（服算法）。**

---

## 3 成因

### 3.1 当前光路

`SimulationProjectedLight` 的实现分四步：

1. **内容烘焙**：正交俯视相机 `(5, 20, 5)`、`orthographicSize = 6`、只拍 layer 31，把格点/高亮/变更环烘成 512² 输出图
2. **光路映射**：`view = Scale(1,1,-1) × TRS(projectorPosition, projectorAngles)⁻¹`，`vp = GetGPUProjectionMatrix(Perspective(fov,1,0.1,50)) × view`
3. **遮挡**：用同一 VP 把接收物画进 512² 深度图（`-viewZ / Far`）
4. **着色**：`albedo × image × incidence × attenuation × strength`，加色混合

问题出在第 1 步：**内容相机是正交的，图案因此被定义在桌面平面上**；而第 2 步的投影是透视的。

### 3.2 数值推导

投影仪位于 `(5, 14, 5)`，积木顶面 `y = 1`，桌面 `y = 0`。

积木顶面上的点 `W = (x, 1, z)` 所在的光线，继续延伸到桌面 `y = 0` 的交点：

```
t = (14 − 0) / (14 − 1) = 14/13 ≈ 1.0769
桌面交点 = 5 + (14/13) × (x − 5)
```

即：**积木顶面看到的是“更靠外 7.69%”那个位置的图案**。偏移量随距离线性增长：

| 距投影仪正下方的距离 | 偏移（格） |
| --- | --- |
| 1 | 0.077 |
| 3 | 0.231 |
| 5（棋盘边缘） | **0.385** |

等价说法：在 `y = 1` 平面上，透视锥的覆盖宽度是 `2 × 13 × tan(23.2°) = 11.14`，而正交图固定覆盖 `12`。同一块 1 单位宽的积木，在两张图里占比分别是 `1/11.14`（8.97%）和 `1/12`（8.33%），相差 7.7% —— 投放时被放大，回不到原位。

### 3.3 为什么“物理正确”并不等于“应该保留”

偏移在单台真实投影仪上确实存在，但真实部署不会接受它：

- 投影映射（projection mapping）的全部意义，就是按现场几何预畸变内容
- 观众扫一眼桌子会发现“中间准、四角不准”，这比整体平移更像故障
- 部署验收里“图案与物体对不齐”属于缺陷，不属于艺术效果

结论：**保留偏移 = 没做部署校正；校正后的投影才是真实部署的样子。**

## 4 方案对比

| 方案 | 做法 | 积木对齐 | 桌面影响 | 改动量 | 真实对应 |
| --- | --- | --- | --- | --- | --- |
| A 平面反畸变 | 内容相机缩到 `6 × 14/13`，标定在 `y = 1` | ✅ | 图案外扩 7.7% | 约 3 行 | 一次性几何校正 |
| **B 投影仪视角烘焙** | 内容相机改为与投影仪同位姿、同 FOV 的透视相机 | ✅ 任意高度 | 无 | 约 15 行 | 投影映射内容管线 |
| C 深度感知 UV | 着色时把采样点推到标定平面再算 UV | ✅ | 可调 | 约 6 行着色器 | 带几何校正的投影仪 |
| 现状 | 正交相机 | ❌ 最大 0.385 格 | — | 0 | 未校正的投影仪 |

三者均**不影响**遮挡、表面反射率、入射角、距离衰减 —— 只改变图案落点，不会把“光”退化成“贴纸”。

方案 C 属于在光路里补偿，投影仪本身并不知道几何；方案 B 与 A 都是“改幻灯片”，与真实投影映射的做法一致。**推荐 B**。

---

## 5 推荐方案 B：投影仪视角烘焙

### 5.1 原理

```text
内容相机 ≡ 投影仪
    → 烘出的图已包含预畸变
    → 投影仪把这张图投回去，每个点回到它被拍下的位置
```

图案本身是贴在格心、`y = 1.006` / `y = 0.006` 的 3D 面片，投影回原处即与格子严格重合，且对任意高度、任意斜投都成立。

### 5.2 代码改动

`SimulationProjectedLight.EnsureResources()` 中，内容相机由

```csharp
contentCamera.orthographic = true; contentCamera.orthographicSize = 6;
contentCamera.aspect = 1;
contentCamera.transform.SetPositionAndRotation(new Vector3(5, 20, 5), Quaternion.Euler(90, 0, 0));
```

改为

```csharp
contentCamera.orthographic = false;
contentCamera.fieldOfView = fieldOfView;
contentCamera.aspect = 1;
contentCamera.nearClipPlane = 0.1f;
contentCamera.farClipPlane = Far;
contentCamera.transform.SetPositionAndRotation(projectorPosition, Quaternion.Euler(projectorAngles));
```

并在每次烘焙前同步位姿（`projectorPosition / projectorAngles / fieldOfView` 在运行时可变）：

```csharp
contentCamera.fieldOfView = fieldOfView;
contentCamera.transform.SetPositionAndRotation(projectorPosition, Quaternion.Euler(projectorAngles));
contentCamera.Render();
```

### 5.3 为什么台面观感不变

`FOV = 46.39718° = 2·atan(6/14)` 是按投影仪高度 14、覆盖 12×12 反推出来的。因此在 `y = 0` 平面上，透视锥覆盖范围与原来的正交图**逐像素一致**；只有 `y > 0` 的物体成像尺寸改变，而这正是需要校正的部分。

### 5.4 建议保留对照模式

引入枚举，正交版本保留：

```csharp
public enum SlideMode { FlatTable = 0, ProjectorBaked = 1 }
```

- 默认 `ProjectorBaked`
- `FlatTable` 保留，用于：
  - 跑现有的、以“高度偏移存在”为前提的图像检查
  - 演示“未校正”与“已校正”的差别

## 6 观感配套：不只是对齐

几何对齐只是第一眼的问题；让人看着舒服还需要以下调整。

| 项 | 现状 | 问题 | 建议 |
| --- | --- | --- | --- |
| 亮度均匀 | `attenuation = min(1.5, 196/d²)` | 角落明显偏暗，像灯泡而非投影 | 加归一化 gain，按到接收面的距离补偿；目标中心/角落差 ≤ 25% |
| 边缘羽化 | `blurPixels = 0.5` | 边缘出现硬阶梯 | 实机建议 2–3 px，或换高斯核；宁可略糊，不要硬边 |
| 亮度上限 | `lightStrength = 1.3` | 白光图案过曝，洗掉积木本色 | 按实测降到刚好不发白；任通道不饱和（< 0.98） |
| 黑场 | `blackLevel = 0` | 实机黑场有残余光 | 用实拍黑帧填充，不能长期留 0 |
| 颜色 | 高亮用满饱和色 | 白墙发灰、红积木发黑，观众分不清是图案还是积木变色 | 饱和度降到 60–70% |
| 阴影方向 | 遮挡来自正上方投影仪 | 与场景左右白光方向不一致时画面显“脏” | 保持光源方向单一且自洽 |
| 闪烁 | 消隐取样会关投影 | 黑一下再亮，读作故障 | 落地走连续投影；消隐仅用于标定 |

## 7 验收清单

| 判据 | 目标值 |
| --- | --- |
| 图案中心与积木中心偏差 | ≤ 2% 格宽（现状 7.7%） |
| 中心与角落亮度差 | ≤ 25% |
| 图案边缘过渡 | ≥ 2 px 羽化，无硬阶梯 |
| 白光图案是否过曝 | 无通道饱和（< 0.98） |
| 帧间亮度波动 | ≤ 2%，无肉眼可见闪烁 |
| 斜投时图案可读性 | 纹样/文字仍可辨认 |

---

## 8 与识别链路的关系

当前识别分支（`feat/continuous-projection-recognition`）使用**合成图**做识别，不读取屏幕渲染结果。这意味着：

- 渲染层可以放心为观感优化（几何校正、亮度补偿、羽化），不影响识别精度
- 一旦把本分支的渲染层与连续投影识别合并，渲染结果会成为相机输入，两个目标重新耦合，届时时序、曝光与动态范围需要统一考虑

## 附录 B 关键公式

```
偏移倍率            k = (h_projector) / (h_projector − h_surface)
                    = 14 / 13 ≈ 1.0769            // h_surface = 1

偏移量（格）        Δ(d) = d × (k − 1)
                    d = 5 时 Δ ≈ 0.385

表面光照贡献        L = albedo × image × saturate(N·L) × min(1.5, 196/d²) × strength
                    albedo = 材质 _Color × _MainTex
                    image  = 5-tap 模糊后的投影图案，lerp 到白场的黑电平修正

遮挡判据            eyeDepth > depth(uv) × Far + bias      → discard
```

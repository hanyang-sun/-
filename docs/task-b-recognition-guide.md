# 任务 B：当前 RGB 识别与确认

更新：2026-11-07。适用当前 Brick2Life-C 本地工作树。初始改动记录已归入 [历史](history/task-b-recognition-changes.md)。

## 输入和模式

顶部按钮或 F8 只切换以下两种模式，默认连续识别。切换保留已确认布局、丢弃待确认计数。

| 模式 | 输入 | 采集时机 |
| --- | --- | --- |
| 连续识别 | C 顶置相机实际带投影 RGB | 自动采集，投影保持点亮 |
| 暂停识别 | 统一门关闭投影后的新 RGB | 按暂停后持续采集；继续/开战前完成新确认再恢复 |

连续模式不使用离屏干净图再合成投影的旁路；`PhotometricComposerFixture` 仅在 Tests 中用于数学回归。暂停模式也不将同一张照片重复计作三帧。搭建视图始终无投影，展示模式不决定识别输入。

## 单帧识别

1. `SimulationCameraCapture` 渲染并读取图像；`SimulationVisionMonitor.LastRecognitionImage` 保存补偿前的实际 RGB。相机固定曝光当前为 0.3，详细成像条件见 [投影手册](physical-projector-guide.md)。
2. `CameraProjection` 根据公开相机参数、棋盘尺寸和预设平面生成采样。每格默认 3×3 个点，横纵位于格内 45%、50%、55%；读取离散像素，不等于整格分割。
3. 连续模式调用 `ProjectedLightRecognizer`：使用本次曝光对应投影输出与公开标定，按 `I = ρ × (A + G × P) + B` 近似恢复反射率，再分类。当前 Gamma 仿真响应指数为 1，不能直接用于实机。
4. 暂停模式调用 `FixedGridRecognizer`，直接对干净 RGB 做相同的归一化颜色距离分类。标准色来自公开调色板，不是当前每格颜色答案。
5. 按最大 RGB 通道归一化，最近标准色距离不超过 0.35，且与第二近距离至少相差 0.12；亮度小于 0.045 为未知，低饱和度（0.16）作为中性棋盘候选。连续模式另拒绝饱和及不可解释的光度恢复。
6. 格内投票至少达到有效采样的 58%，并超过其他结果；9 点有效时需 6 票。连续模式还从同一 RGB 检查高度 0 的棋盘平面与高度 1 的假设顶面，按限制条件合并空格结果，不是在测量高度。

## 稳定、变化与评价

`LayoutChangeTracker` 当前要求 100 格全部明确，连续三次采集一致才确认；未知会打断候选计数，保留上次确认。稳定时约 0.8 秒采样，可用候选约 0.12 秒补足确认，快速阶段最多一秒；这些是调度间隔，不是端到端延迟承诺。

首次稳定只建立基线。后续比较占用与颜色；同色唯一的一减一增可推断 Move，多候选保留歧义。若移动过程的空布局先被确认，事件可表现为 Remove 再 Add，不声称跟踪了物理实例。

确认链为 `TopCamera RGB → Recognizer → LayoutChangeTracker → BoardSyncSession → BoardUpdate → C`。真值快照与 `RecognitionScore` 仅用于预测后的评价，不决定开战或是否采用新布局。公开色样、相机和投影标定可以输入识别；当前占用、颜色、ID、接收物真实材质与遮挡深度不由投影适配传给分类器。

## 限制和验收

当前是固定 10×10、单层、预设彩色积木的受控仿真。尚未完成真实照片闭环、多层高度、任意姿态、手部处理及实机光度/时间同步。一个格子未知可能阻塞整体提交，投票置信度也不是经校准的正确概率。

现行联调入口为 `LiveProjectionRefreshChecks`、`PauseRecognitionChecks`、`PhysicalProjectorChecks` 与纯 C# 检查。命令和最后结果见 [验证摘要](verification/current-simulation.md)。旧初版样例的 100/100 不表示所有投影和光照条件下的准确率。

# 实拍扫描拒绝与面板遮挡修复

Status: ready-for-agent
Completion: complete (2026-10-09)

## 请求与验收

修复用户截图中的异常拒绝与地图遮挡。沿用 Unity 内的角色标定。完整原图须在用户实际保存的标定下识别到 10 个方块；真正裁切的照片保持拒绝并标出可定位的错误区域；不能覆盖当前关卡。照片界面遮住三维地图。既有格纸、无格纸、同色紧贴、角色互换、示例和确认流程保持通过。

编码前已按 AGENTS 的 GitHub 规则完成 [候选比较与适配方案](../../docs/research/scan-rejection-github.md)。

## 最小复现与因果证据

使用保存扫描的 `source.jpg`、解码 RGB、`result.json` 内的 palette 与 settings 直接调用公开识别器。

1. 完整图 1080×2449，在背景 `(65,61,63)`、白 `(251,251,251)`、橙 `(253,97,48)`、蓝 `(5,195,254)` 下稳定返回 `BRICK_CROPPED`。与旧的开发者自行选点通过不是同一标定。
2. 分割诊断显示原图出现颜色编号 4 的未知组件，原坐标约 `(0,924)`、大小 `705×1527`，覆盖亮灰背景并触及画面左/下边缘。三个独立方块尺度锚点为 55、64、65（降采样后），单位尺寸 64。
3. 单独把背景样本改为 `(650,850)` 的 `(90,78,84)`，单位尺寸与积木组件不变，未知背景组件消失，恢复 10 块。由此确认是背景明度变化进入未知前景，而非单位尺寸估计错误。
4. 截图实际导入的是 958×938 的 `qq_pic_merged_1791536977046.jpg`。原文件可直接看到对象被边缘截断；旧、新代码均返回拆分不确定和两项裁切。不能通过忽略全部触边物体消除报错。
5. 界面以真实 Game 视图截图最小复现：无控件间隙的 46 个像素样本 RGB 范围差 82，地图透出可见。只依赖 Camera.Render 的截图不会包含 IMGUI。

临时生产分割输出已移除。原始诊断数据保留在 `debug/`。

## 实施

- 在低饱和背景与像素色彩一致时，用已标定低饱和积木的亮度和已有颜色距离/间隔设置计算可靠前景亮度下限，允许背景明度渐变。保留白色方块前景，不硬编码实物 RGB 或文件名。
- 保留未知颜色、真正触边、几何残差和逐单元 55% 覆盖检查。没有整体放宽拆分阈值。
- `Issue.ImageRegion` 可选携带原图区域；拒绝时不返回可确认的部分地图。界面绘制红框，报告增加 `issues[].region`。无区域错误使用空数组，现有构造调用兼容。
- GUI 控件前绘制不透明全窗口底层，恢复 GUI 状态。拒绝的数字地图提示检查红框。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 完整保存扫描回放，实际 palette/settings | 修复前拒绝，修复后 `Success`、10 块；退出码 0 |
| 实际裁切扫描回放 | `Rejected`、`BRICK_SPLIT_UNCERTAIN, BRICK_CROPPED, BRICK_CROPPED`；预期拒绝，退出码 0 |
| 新拒绝回归 | 用户标定、灰背景 75→180 渐变、1/7/2 颜色数量、错误区域、当前关卡保留；通过 |
| 全部 .NET 检查 | 含 200 个独立 BFS 对照布局及已有照片/颜色/流程检查；退出码 0 |
| Unity 6000.3.24f1 隔离场景回归 | 原 PNG、原 JPG、实际标定、10 块 Renderer、两个示例、确认、报告保存和拒绝区域往返一致；退出码 0 |
| 实际 Game 视图界面截图 | 1110×740，同一间隙的 46 个样本范围差由 82 降至 0；另在用户相同的 862×678 尺寸验证范围差 0；均退出码 0 |

界面截图来自隐藏启动的隔离编辑器：无 Game 视图的 batch 模式无法生成 ScreenCapture，首次检查超时，未计为通过；改为带实际 Game 视图的隔离编辑器后先复现失败、再验证修复。小窗口验证使用独立 Game 视图调到实际 862×678；首次因 Play 重载后窗口标题改变而未找到窗口，改为按窗口类型及非停靠属性重新获取后通过。上述验证辅助失败均保留日志。不改动或关闭用户原编辑器项目。
